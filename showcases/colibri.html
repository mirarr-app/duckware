The living cortex

Watch every expert fire.

Colibrì is not a black-box API wrapper. It is a microscope for Mixture-of-Experts inference: routing heat decides which specialists earn VRAM, which stay pinned in RAM, and which stream from NVMe — without quietly changing the model.

A JIT — but for weights

GLM-5.2 activates ~40B parameters per token, and only ~11 GB of those change from token to token. The dense spine stays resident; the routed experts are staged on demand with a per-layer LRU, a learned hot-store, and one-layer-ahead prefetch.

Insufficient fast memory may slow you down. It must never redefine precision or router semantics. That honesty is the research stance.

What it actually is

Frontier MoE, hummingbird rations.

Named for a bird that weighs grams and visits a thousand flowers a day, Colibrì keeps a 744-billion-parameter giant alive on 25 GB of RAM, twelve cores, and a lot of disk patience — or scales up to full expert residency on multi-GPU hosts.

The runtime path is deliberately tiny: a single C file plus small headers. No BLAS, no Python at inference time, no GPU required. Optional CUDA and Metal backends share one placement model with the CPU path.

Experimental by design. Optimizations graduate only when end-to-end measurements — throughput, TTFT, quality, correctness — earn them.

Why it stands out

Three bets that stick.

01 · HIERARCHY

Placement, not fitting

VRAM, RAM, and NVMe are tiers for the same weights. Limited fast memory changes speed — never silently changes the model you think you are running.

02 · STREAMING

I/O is the engine

Batched expert unions, overlapped reads, O_DIRECT, dual-SSD striping, and router lookahead treat storage latency as a first-class problem instead of pretending it is free.

03 · HONESTY

Measure or it did not happen

Token-exact forward validation, published benchmarks from community machines, and speculation that can be turned off when acceptance does not repay verification.
